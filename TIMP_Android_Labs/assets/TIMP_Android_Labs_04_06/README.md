# TIMP Mobile — адаптированные лабораторные №4–6

Три задания преподавателя в старом формате Xamarin.Forms преобразованы под **существующий** нативный Android-проект `~/AndroidStudioProjects/puzzle` на **Kotlin + Jetpack Compose (Material 3)**, разрабатываемый в VS Code и проверяемый в Android Emulator.

| Новая лабораторная | Исходный Word-файл | Тема | Инструкция |
|---|---|---|---|
| №4 | `Xamarin_zadanie_4.docx` | Frame, Picker, Stepper, Slider | [ЛР №4](lab_04_frame_picker_stepper_slider.md) |
| №5 | `Лаба5.docx`, **заголовок внутри «Xamarin 6»** | TimePicker и часовые пояса | [ЛР №5](lab_05_timezone_picker.md) |
| №6 | `Лаба6.docx`, заголовок «Xamarin 6» | Grid, Switch, таймер | [ЛР №6](lab_06_grid_switch_timer.md) |

## Что сохранено из оригиналов

- №4: синий Frame с добавлением Label; независимые отступы `left/top/right/bottom`, Picker, кнопки `−/+`, Slider высоты, тень и радиусы скругления 0/10/20/30.
- №5: текущее время устройства, выбор часового пояса, текущее время выбранной зоны.
- №6: сетка 3×3 с исходными девятью цветами, добавление по одной ячейке в секунду, Switch справа внизу, автоотключение и возврат к 3×3 при заполнении доступного пространства.

## Адаптационные решения

В Jetpack Compose не все Xamarin-компоненты существуют под теми же именами. Поэтому Frame представлен контейнером с тенью/скруглением, Stepper — двумя кнопками, Picker — выпадающим списком. В ЛР №5 текущие часы показываются индикаторами **только для чтения**, а не редактируемыми пикерами времени. Эти решения указаны в соответствующих документах.

Численные ограничения, не заданные преподавателем, в заданиях отмечены как **предлагаемые значения** и должны быть задокументированы в отчёте. Обязательные свойства и поведение оригиналов сохранены.

## Порядок работы

1. Передать агенту **один** файл лабораторной вместе с контекстом существующего проекта.
2. Создавать отдельные ветки `feature/lab-04`, `feature/lab-05`, `feature/lab-06` последовательно от актуальной ветки с уже выполненными лабораторными.
3. Добавлять экран новой лабораторной в текущее общее меню; не заменять старые экраны.
4. Проверять сборку `./gradlew clean assembleDebug` и установку `./gradlew installDebug`.
5. Подготовить отчёт и скриншоты фактической работы на эмуляторе; не писать `BUILD SUCCESSFUL`, пока команда реально не выполнена.

Иллюстрации оригинальных Word-документов находятся в [`assets/`](assets/).

# Отчёт по лабораторной работе №4

## Цель

Изучено динамическое добавление содержимого в Compose-контейнер, управление
отдельными внутренними отступами, высотой, тенью и скруглением углов.

## Исходная постановка и интерпретация

В адаптации `Frame` заменён заметным синим Compose-контейнером на основе
`Surface`/`Modifier`. Синий контейнер считается целью изменения отступов:
исходная ссылка на компонент предыдущего задания интерпретирована как
контейнер на самом экране лабораторной №4.

## Соответствие Xamarin и Compose

| Xamarin | Compose |
|---|---|
| `Frame` | `Surface` и `BoxWithConstraints` |
| `Label` | `Text` |
| `Button` | `Button` / `OutlinedButton` |
| `Picker` | `DropdownMenu` |
| `Stepper` | Кнопки `−` и `+` |
| `Slider` | `Slider` |
| `HasShadow` | `Switch` |
| `CornerRadius` | `RadioButton` |

## Состояния и структура

Реализация находится в
[Lab4Screen.kt](../app/src/main/java/com/example/puzzle/Lab4Screen.kt).

Используются отдельные состояния для:

- количества меток;
- независимых отступов `left`, `top`, `right`, `bottom`;
- выбранной стороны Picker;
- высоты контейнера;
- включения тени;
- радиуса скругления.

Числовые параметры:

- шаг отступа: `4 dp`;
- диапазон отступа: `0–64 dp`;
- начальная высота Frame: `64 dp`;
- верхняя граница высоты: до `240 dp`;
- максимальное количество меток: `20`;
- варианты радиуса: `0`, `10`, `20`, `30 dp`;
- тень: `12 dp`.

При добавлении меток дополнительное содержимое прокручивается внутри синего
контейнера. Ограничение в 20 меток предотвращает бесконечный рост интерфейса.

## Максимальная высота

Экран использует `WindowInsets.safeDrawing` и `BoxWithConstraints`, поэтому
расчёт учитывает безопасную область окна после системных панелей и текущую
доступную высоту. `Modifier.onSizeChanged` измеряет фактические высоты заголовка
и всего блока управления (добавление Label, Picker/Stepper, Slider, HasShadow,
CornerRadius). Измерения используются только при совпадении ширины с текущей
шириной содержимого, чтобы значения от предыдущей ориентации не применялись
после поворота.

Формула верхней границы:

```kotlin
maxFrameHeight =
    (maxHeight - measuredHeaderAndControls - 20.dp - 32.dp)
        .coerceIn(64.dp, 240.dp)
```

`20.dp` — два фактических интервала `Arrangement.spacedBy(10.dp)` по обе стороны
Frame; `32.dp` — верхний и нижний padding экрана по `16.dp`. `240.dp` — выбранный
абсолютный максимум контейнера, а не резерв для управляющих элементов.
`64.dp` — безопасный минимум. Если на маленьком экране управляющие элементы
вместе с минимумом не помещаются, экран прокручивается.

Значение Slider ограничивается новым диапазоном при каждом изменении
максимальной высоты. `LaunchedEffect` также записывает ограниченное значение в
сохраняемое состояние после поворота. При диапазоне без свободного интервала
(верхняя граница равна `64.dp`) Slider отключён. Поэтому его значение не выходит
за `valueRange`.

## Основные фрагменты

Добавление меток:

```kotlin
Button(onClick = { if (labelCount < 20) labelCount += 1 }) {
    Text("Добавить Label")
}
```

Смена выбранного отступа:

```kotlin
val current = when (selectedSide) {
    "left" -> leftPadding
    "top" -> topPadding
    "right" -> rightPadding
    else -> bottomPadding
}
setter((current + delta).coerceIn(0, 64))
```

Одинаковая форма для фона, границы и тени:

```kotlin
val shape = RoundedCornerShape(cornerRadius.dp)
Surface(
    modifier = Modifier.fillMaxWidth().height(frameHeight),
    shape = shape,
    color = Color(0xFF1976D2),
    border = BorderStroke(1.dp, Color(0xFF0D47A1)),
    shadowElevation = if (hasShadow) 12.dp else 0.dp
) {
    // содержимое контейнера
}
```

## Исправления после проверки

- Фиксированный приблизительный резерв `300.dp` удалён. Теперь измеряются
  реальные размеры заголовка и полной группы остальных элементов управления;
  в расчёт также входят реальные значения отступов и интервалов экрана.
- При изменении ширины (в том числе после поворота) старые измерения временно
  не используются: до завершения новых замеров Frame временно ограничен
  безопасными `64.dp`. Новые замеры пересчитывают доступную высоту без цикла
  рекомпозиций: состояние обновляется только когда измеренный размер изменился.
- На эмуляторе в портретной ориентации Slider достиг `240.dp`, и кнопка, Picker,
  Stepper, HasShadow и CornerRadius остались доступны. После установки высоты
  `240.dp` и поворота в альбомную ориентацию верхняя граница стала `64.dp`,
  сохранённая высота была ограничена до `64.dp`; управляющие элементы доступны
  прокруткой. При возврате в портретную ориентацию Slider снова получил
  диапазон до `240.dp`.
- Тень теперь задаётся штатным `Surface.shadowElevation` (`12.dp`/`0.dp`).
  `Surface` использует одну и ту же `shape` для контейнера и тени; отдельный
  `clip()` перед тенью удалён, поэтому внешняя тень не обрезается.
- Проверены все сочетания:

  | HasShadow | CornerRadius | Результат |
  |---|---:|---|
  | Off | 0 dp | Прямоугольник без тени |
  | On | 0 dp | Прямоугольник с видимой тенью |
  | Off | 30 dp | Скруглённый контейнер без тени |
  | On | 30 dp | Скруглённый контейнер с видимой тенью |

- Дополнительно добавлены 20 меток: кнопка добавления отключилась на лимите,
  метки прокручивались внутри Frame. Проверены независимые значения всех
  четырёх отступов (по `4.dp`), возврат в меню и открытие лабораторных №1–3.

## Проверка

На эмуляторе `Pixel_10a` проверены:

1. Синий контейнер и органы управления.
2. Добавление нескольких меток, ограничение на 20 меток и их внутреннюю прокрутку.
3. Независимое изменение каждого из четырёх отступов по шагу `4 dp`.
4. Выбор стороны `bottom` и обновление её числового значения.
5. Picker с вариантами `left`, `top`, `right`, `bottom`.
6. Минимальная и максимальная высота, включая доступность элементов управления.
7. Поворот устройства с пересчётом Slider и прокруткой на маленькой доступной высоте.
8. Все четыре комбинации HasShadow/CornerRadius из таблицы.
9. Прокрутка меток внутри Frame и ограничение их количества.
10. Возврат в меню и доступность лабораторных №1–3.

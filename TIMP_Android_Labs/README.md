# TIMP Mobile — лабораторные работы 1–3

Адаптация исходных заданий по **Xamarin.Forms** для **нативного Android-приложения на Kotlin и Jetpack Compose**.

## Наше окружение

| Компонент | Используем |
|---|---|
| ОС | Ubuntu (на рабочем компьютере) |
| Редактор | Visual Studio Code |
| Android Studio | Создание проекта, Android SDK и Android Virtual Device (AVD) |
| Язык | Kotlin |
| UI | Jetpack Compose + Material 3 |
| Сборка | Gradle Wrapper (`./gradlew`) |
| Запуск и диагностика | Android Emulator, `adb`, `logcat` |
| Существующий проект | `~/AndroidStudioProjects/puzzle` |

> Важно: это **не** инструкция по созданию нового проекта. Все лабораторные выполняются **в уже созданном проекте `puzzle`**. Точное имя пакета смотрите в `MainActivity.kt` и `app/build.gradle.kts`: оно может отличаться от примеров. Изменять версии Gradle, Kotlin и Android Gradle Plugin ради выполнения заданий не нужно.

## Перед началом

Проверьте, что ошибка выбора JDK для Gradle устранена и сборка завершается успешно:

```bash
cd ~/AndroidStudioProjects/puzzle
./gradlew --version
./gradlew assembleDebug
```

Если настройка Gradle Daemon по-прежнему требует Java 25, а сборка падает на отсутствующем `jlink`, сначала исправьте конфигурацию JDK. Работающий эмулятор **не подтверждает**, что APK уже собирается.

Запустите ранее созданный эмулятор (подставьте имя из списка):

```bash
emulator -list-avds
emulator -avd ИМЯ_ВАШЕГО_AVD
```

В другом терминале:

```bash
adb devices
./gradlew installDebug
```

Для просмотра ошибок:

```bash
adb logcat -s AndroidRuntime:E
```

## Где писать код

Откройте проект командой:

```bash
code ~/AndroidStudioProjects/puzzle
```

Основная точка входа: `app/src/main/java/<ваш_пакет>/MainActivity.kt`. Если у вас шаблон Compose, он содержит `setContent { ... }`. Создавайте дополнительные Kotlin-файлы **в том же пакете или его подпакетах**, например:

```text
app/src/main/java/<ваш_пакет>/
├── MainActivity.kt
└── ui/
    └── screens/
        ├── Lab1Screen.kt
        ├── Lab2Screen.kt
        └── Lab3Screen.kt
```

Структура рекомендательная: для начала можно выполнять лабораторные по очереди, временно подставляя нужный экран в `setContent`. Если делаете общий экран выбора лабораторных, это дополнительная часть вашей реализации, а не обязательное требование исходных документов.

## Как сдавать

Для каждой лабораторной: исходный Kotlin-код, скриншоты рабочего приложения в эмуляторе, ответы на теоретические вопросы (где предусмотрены) и краткое описание проверки. Можно вести всё в одной ветке проекта либо делать отдельные ветки `lab-01`, `lab-02`, `lab-03`.

**Отличие от оригинала:** Xamarin.Forms, C#, UWP и запуск iOS заменены нативным Android на Kotlin. Кроссплатформенная часть первой работы **не может быть технически эквивалентно выполнена** в выбранном стеке: это явно отмечено в её тексте и требует согласования с преподавателем.
